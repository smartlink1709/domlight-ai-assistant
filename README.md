# ДомЛайт — AI-консультант магазина

## Демонстрация

[Посмотреть видео работы «ДомЛайт»](https://disk.yandex.ru/i/J8FiNvIrwvqO-g)

Учебный проект магазина роботов-пылесосов: посетитель сравнивает товары, уточняет требования в чате и оформляет тестовую заявку. Менеджер получает карточку в Telegram; данные сохраняются в PostgreSQL и Google Таблице.

Магазин, товары и цены вымышлены. Реальные заказы и оплата не предусмотрены.

## Возможности

- Каталог с поиском, фильтрами и сравнением до трёх моделей.
- Подбор по бюджету, площади, коврам, животным и влажной уборке.
- Ответы GigaChat по каталогу и базе знаний.
- История диалогов, тестовые контакты и демонстрация согласия.
- Обновление карточки Telegram и строки Google Таблицы по ID чата.
- Кнопки менеджера: взять в работу, выключить автоответы, отметить спам.

**Стек:** Python 3.11, FastAPI, Uvicorn, Pydantic, PostgreSQL, GigaChat API, Telegram Bot API, Google Sheets API, HTML/CSS/JavaScript.

## Режимы запуска

| Режим | Что нужно | Что доступно |
|---|---|---|
| Просмотр интерфейса | Браузер; открыть `static/index.html` | Каталог и сравнение; чат отключён |
| Локальное приложение | Python и PostgreSQL | История, подбор по правилам, тестовая заявка |
| AI-консультант | Дополнительно собственный ключ GigaChat | Ответы на свободные вопросы и извлечение пожеланий |
| Уведомления и учёт | Собственные доступы Telegram и/или Google | Карточки менеджера и/или таблица заявок |

Без ключа GigaChat работает ограниченная анкета. При ошибке API или некорректном ответе модели приложение сообщает об этом и продолжает подбор по правилам. Внешние API могут требовать оплаты по условиям поставщика.

## Локальный запуск в Windows

### 1. Подготовьте окружение

Установите Python 3.11 и PostgreSQL (проект проверялся с PostgreSQL 17). Для создания базы удобно использовать pgAdmin. Служба PostgreSQL должна быть запущена.

Скачайте репозиторий через **Code → Download ZIP** и распакуйте архив. Откройте PowerShell в папке, где лежат `main.py`, `requirements.txt` и `schema.sql`.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

Активация окружения не требуется: команды явно используют его Python. Основной файл должен называться именно `main.py`.

### 2. Создайте базу данных

1. В pgAdmin подключитесь к своему серверу PostgreSQL.
2. Нажмите **Databases → Create → Database** и создайте базу `domlight_bot`.
3. Откройте **Query Tool** этой базы, вставьте всё содержимое `schema.sql` и выполните его.
4. В `.env` укажите параметры своего подключения:

```dotenv
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=domlight_bot
DB_USER=postgres
DB_PASSWORD=ВАШ_ПАРОЛЬ
```

Используйте отдельную базу для демонстрации. В PostgreSQL сохраняется история всех чатов; кнопка «Новый чат» не удаляет предыдущую историю.

### 3. Подключите GigaChat — по желанию

В кабинете разработчика GigaChat получите собственный ключ авторизации API. Укажите его в `.env` как `GIGACHAT_CREDENTIALS`; задайте `GIGACHAT_SCOPE` для своего типа аккаунта и доступную ему модель в `GIGACHAT_MODEL`.

Это доступ к API, а не пароль от веб-чата. Для HTTPS код использует файл `certs/ca_bundle.pem`; он должен присутствовать. Не отключайте проверку сертификатов при ошибке подключения.

Если хотите сначала проверить приложение без нейросети, оставьте `GIGACHAT_CREDENTIALS` пустым.

### 4. Запустите сайт

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

Дождитесь `Application startup complete` и откройте **http://127.0.0.1:8000/**. Оставьте терминал работающим; для остановки нажмите **Ctrl + C**.

Запускайте только один сервер на порту 8000. После изменения `.env` вручную остановите и запустите заново сервер и обработчик Telegram, если он используется.

## Telegram — необязательная интеграция

1. Создайте собственного бота через **@BotFather** командой `/newbot`.
2. Добавьте бота в отдельную тестовую группу и разрешите отправку сообщений.
3. Укажите в `.env` токен и числовой ID группы:

```dotenv
TELEGRAM_BOT_TOKEN=ВАШ_ТОКЕН
TELEGRAM_CHAT_ID=ID_ГРУППЫ
```

ID — это значение `message.chat.id` из ответа Bot API `getUpdates`, не имя группы и не ссылка-приглашение. Для группы он обычно отрицательный; сохраняйте знак минус.

Если ID неизвестен: остановите другие обработчики этого бота, отправьте в группу `/start@имя_бота`, затем выполните команду ниже из папки проекта. Она читает токен локально и выводит только названия и ID групп:

```powershell
.\.venv\Scripts\python.exe -c "from main import bot_api; groups={(m['chat']['id'],m['chat'].get('title','')) for u in bot_api('getUpdates',{}) for m in [u.get('message',{})] if m.get('chat',{}).get('type') in ('group','supergroup')}; print(groups or 'Группа не найдена: отправьте команду боту в группе и повторите.')"
```

Перезапустите сервер и отправьте сообщение в новом чате сайта. Карточки отправляет сам сервер. Для работы **кнопок менеджера** дополнительно откройте второй PowerShell в той же папке и запустите:

```powershell
.\.venv\Scripts\python.exe .\main.py --telegram-worker
```

Для одного токена используйте только один обработчик `getUpdates` и бота без настроенного webhook. В этой версии Telegram служит панелью менеджера, а не чатом покупателя. Взятие заявки в работу выключает автоответы; обратного включения кнопкой пока нет.

## Google Таблица — необязательная интеграция

1. В своём проекте Google Cloud включите **Google Sheets API**.
2. Создайте сервисный аккаунт и получите его JSON-ключ.
3. В папке приложения создайте каталог `secrets` и сохраните ключ как `secrets/google-service-account.json`.
4. Создайте Google Таблицу с листом **Лиды**.
5. Вставьте содержимое `sheets_headers.tsv` в ячейку **A1**: должны заполниться 14 столбцов, от A до N. Не меняйте названия и порядок; столбец «Компания» в этом сценарии остаётся пустым.
6. Из JSON-ключа скопируйте адрес `client_email`. В настройках доступа таблицы добавьте его с ролью **Редактор**.
7. Заполните `.env`:

```dotenv
GOOGLE_SHEET_ID=ID_ТАБЛИЦЫ
GOOGLE_SHEET_TAB=Лиды
GOOGLE_SERVICE_ACCOUNT_FILE=secrets/google-service-account.json
```

ID таблицы — часть её адреса между `/d/` и `/edit`. Проверка доступа:

```powershell
.\.venv\Scripts\python.exe .\main.py --check-sheets
```

Ожидаемый результат: `Подключение к Google Таблице работает. Лист и заголовки проверены.` Затем перезапустите работающие процессы приложения.

Строка создаётся после сообщения в чате, а затем обновляется по тому же ID. Запись идёт в фоне после попытки обновить Telegram, поэтому при сетевом сбое возможна задержка. Ручная синхронизация всех сохранённых чатов:

```powershell
.\.venv\Scripts\python.exe .\main.py --sync-sheets
```

## Проверка основного сценария

В новом чате отправьте: **«Квартира 60 м², есть кошка, бюджет до 30 000 ₽»**. На вопросы о коврах и влажной уборке ответьте **«да»**, затем:

1. `Выбираю DL Pet`
2. `Ульяновск`
3. `Анна Тестовая`
4. `Согласна`
5. `+7 000 000-00-00`

Ожидаемый результат: «Тестовая заявка оформлена». При настроенных интеграциях прежняя карточка Telegram и строка таблицы обновляются: появляются тестовые контакты и статус «Заявка».

Для свободного вопроса с подключённым GigaChat: **«Сколько стоит DL Pet и подходит ли для шерсти?»**. Для передачи сотруднику: **«Позовите менеджера»** — после этого автоответы в данном чате приостанавливаются.

## Если что-то не работает

| Проблема | Что проверить |
|---|---|
| Не найден `requirements.txt` или `main.py` | PowerShell открыт в корне распакованного проекта; файл называется `main.py` |
| Ошибка PostgreSQL | Служба запущена, пароль верный, база создана, `schema.sql` выполнен |
| Интеграция «отключена: доступы не заданы» | Заполнен именно `.env`, файл сохранён, процессы перезапущены |
| Telegram: `URLError` / `WinError 10060` | Соединение Python с Telegram; расширение VPN в браузере не обеспечивает подключение Python |
| Первая отправка Telegram не подтверждена | Проверьте группу; после восстановления сети тестируйте в новом чате — автоматический повтор первой отправки ограничен во избежание дублей |
| Google: `FileNotFoundError` / HTTP 403 | Путь к JSON-ключу, включённый API, доступ «Редактор» для `client_email` |
| Ответ модели не разобран | Работает резервная анкета; повторите свободный вопрос и проверьте лог сервера |
| Страница работает, а в терминале нет запросов | Не запущена ли другая копия сервера |

## Состав проекта

- `main.py` — сервер, сценарий подбора, сохранение данных и интеграции.
- `static/index.html` — интерфейс магазина и чата.
- `data/catalog.json` — учебный каталог товаров.
- `data/knowledge.md` — сведения и правила ответов о магазине.
- `certs/ca_bundle.pem` — публичные сертификаты для HTTPS-соединения с GigaChat.
- `schema.sql` — таблицы PostgreSQL.
- `sheets_headers.tsv` — заголовки Google Таблицы.
- `requirements.txt`, `.env.example`, `.gitignore` — зависимости и настройки.

При изменении каталога перезапустите сервер. Страница приложения получает актуальный каталог; отдельно открытый HTML содержит сохранённый снимок каталога.

## Безопасность и границы MVP

В репозиторий не должны попадать `.env`, каталог `secrets`, выгрузки базы, логи и реальные контакты. `.env.example` содержит только пустые поля для ключей и паролей. При загрузке файлов через браузер GitHub проверяйте список вручную: наличие `.gitignore` не заменяет эту проверку.

Используйте только вымышленные данные и тестовый телефон. Приложение предназначено для локальной демонстрации: у API нет авторизации и ограничений частоты запросов. Для размещения в интернете необходимы отдельная защита доступа, контроль расходов API и доработка надёжности. Маскирование телефонов перед LLM не заменяет полноценную защиту персональных данных.
